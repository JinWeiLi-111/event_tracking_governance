# 存量埋点治理：业务场景知识（场景命中版）

> 本文档不是通用术语表，而是“场景 -> 字段归一结果”的知识库。  
> 目标：当埋点命中特定业务模式时，页面位置、功能名称、事件类型保持业务一致性。

## 1. 使用方式

- 先按 `英文名/中文名/描述` 判断是否命中某个场景规则。
- 命中后，优先使用该场景的归一建议。
- 所有结果仍需通过 `configs/hard_constraints.json` 校验。
- 若场景规则与 `docs/workflow.md` 冲突，以 `docs/workflow.md` 为准。

## 2. 场景匹配优先级

1. 英文名前缀或正则（最稳定）
2. 埋点中文名关键词
3. 埋点描述关键词
4. 页面位置原值（辅助证据）

## 3. 场景规则清单

### SCN_LIST_REFRESH_RECOMMEND

- 场景说明：列表刷新类埋点（你提到的核心场景）。
- 匹配条件（满足任一即可）：
  - `埋点英文名` 以 `list` 开头
  - `埋点描述` 包含 `刷新列表`、`下拉刷新`、`重新拉取列表`
- 归一目标：
  - 事件类型：`浏览`
  - 功能名称：`推荐列表刷新`
  - 页面位置：优先匹配“推荐相关”页面路径（必须来自 `configs/enums/page_locations.json`）
- 约束说明：
  - 功能名称不得出现 `点击/曝光/浏览/时长/其他` 等事件词
  - 页面位置若无高置信匹配，按服务端/非服务端规则走兜底

### SCN_SEARCH_RESULT_BROWSE

- 场景说明：用户进入或查看搜索结果列表。
- 匹配条件（建议同时满足两项）：
  - `埋点英文名` 包含 `search` 或 `result_list`
  - `埋点描述` 包含 `搜索结果`、`检索结果`
- 归一目标：
  - 事件类型：`浏览`
  - 功能名称：`搜索结果列表查看`
  - 页面位置：搜索结果对应枚举路径

### SCN_DETAIL_PAGE

- 场景说明：用户查看xx详情（比如boss查看牛人卡片详情、牛人查看boss发布职位详情等）
- 匹配条件:
  - `埋点英文名` 以 `detail` 开头
- 归一目标：
  - 事件类型：`点击`
  - 功能名称：`查看xx详情页`（xx需要你自行判断）
  - 页面位置：与详情相关的枚举页面位置

### SCN_JOB_PUBLISH_OR_CHANGE_GOVERN

- 场景说明：职位的发布修改管理
- 匹配条件：
  - 在BOSS直聘业务中，只有老板，也就是boss，可以发布职位，根据埋点所有基础信息字段来匹配该埋点是否是职位发布或者修改管理场景
- 归一目标:
  - 事件类型：`点击`
  - 功能名称：`职位发布` 或者 `职位管理`
  - 页面位置：只能是B端的职位相关页面（必须是B端！！！）

### SCN_EXPECT_JOB_PUBLISH_OR_CHANGE_GOVERN

- 场景说明：牛人期望职位的发布修改管理
- 匹配条件:
  - 在BOSS直聘业务中，只有牛人，也就是geek，可以发布期望求职职位，根据埋点所有基础信息字段来匹配该埋点是否是期望职位发布或者修改管理场景
- 归一目标:
  - 事件类型：`点击`
  - 功能名称：`职位发布` 或者 `职位管理`
  - 页面位置：只能是C端的职位相关页面（必须是C端！！！）

### SCN_EXCHANGE_PHONE

- 场景说明：boss与牛人交换电话
- 匹配条件：判断埋点基础信息中是否出现交换电话，相关字眼。
- 归一目标:
  - 事件类型：`点击`
  - 功能名称：`交换电话`
  - 页面位置：选择消息详情相关的页面位置即可

### SCN_BIZ_OR_BLOCK

- 场景说明：商业阻断场景，BOSS直聘商业化包含商品详情和阻断详情，阻断是
- 匹配条件：
  - `埋点英文名`中含有block
  - 埋点描述或埋点中文名称出现商业阻断相关词语
- 归一目标：
  - 事件类型：根据历史信息、埋点描述来判断
  - 功能名称：按照workflow.md正常推断得出功能名称
  - 页面位置：选择阻断相关的页面位置

### SCN_READ_MESSAGES

- 场景说明：用户在消息详情页中阅读消息并完成已读
- 匹配条件：
  - `埋点英文名`中含有read
  - 埋点描述或埋点中文名称出现已读相关词语
- 归一化：
  - 事件类型：浏览
  - 功能名称：已读消息
  - 页面位置：选择消息详情相关的页面位置即可

### SCN_ITEM_TOOL

- 场景说明：BOSS 直聘商业化道具相关埋点。
- 匹配条件（满足任一即可）：
  - 任一字段（`埋点中文名`/`埋点英文名`/`埋点描述`/`功能名称`）命中 `configs/enums/B_items.json` 的 `tool_names`
  - 任一字段命中 `configs/enums/C_items.json` 的 `tool_names`
- 归一目标：
  - 事件类型：按埋点语义归一（如 click/show/view/other -> 点击/曝光/浏览/其他）
  - 功能名称：保留道具语义（道具名、道具动作、道具效果）
  - 页面位置：
    - 命中 B 端道具时优先 `Web_B-道具` 及其子路径
    - 命中 C 端道具时优先 C 端道具相关页面
    - 同时命中 B/C 时允许多页面位置
- 约束说明：
  - 禁止在命中道具后退回到非道具无关页面（除非证据明确且通过校验规则）
  - 若无法匹配到任何合法道具页面位置，再按 workflow 兜底逻辑处理

## 4. 冲突处理

- 多场景同时命中时，使用“匹配优先级”高者。
- 同优先级冲突时，取关键词命中数更多的场景。
- 仍无法判定时：
  - 事件类型取更保守值 `其他`
  - 页面位置按 `workflow` 中兜底逻辑处理
  - 在结果中标记“场景未确定”

## 5. 正反例（围绕 list--）

### 正例 1

- 输入：
  - 埋点英文名：`list--refresh_recommend_job`
  - 埋点描述：用户下拉后刷新推荐职位列表
- 输出建议：
  - 事件类型：`浏览`
  - 功能名称：`推荐列表刷新`
  - 页面位置：推荐相关页面位置（枚举集合内部）

### 反例 1

- 输入：
  - 埋点英文名：`list--refresh_recommend_job`
  - 功能名称：`刷新列表浏览`
- 问题：
  - 功能名称混入事件词 `浏览`
- 修正：
  - 功能名称改为 `推荐列表刷新`
  - 事件类型单独保留 `浏览`

## 6. 维护要求

- 每新增一个业务模式，新增一个 `SCN_*` 场景条目。
- 每个场景至少包含：匹配条件、归一目标、1 正例 + 1 反例。
- 优先沉淀“高频错判场景”，不要先追求覆盖全部场景。

# 存量埋点治理校验规则（严格执行）

> 本文档定义治理结果的强校验门禁。  
> 目标：明确“必须满足”的规则与“绝对禁止”的错误，确保批量治理结果可直接复核与落库。

## 1. 适用范围

- 适用于每条埋点治理产物的 `completed_fields` 校验。
- 校验字段范围：
  - 埋点id
  - 页面位置
  - 功能名称
  - 事件类型
  - 埋点中文名
  - 埋点英文名
  - 埋点描述

## 2. 必须严格遵循（Must）

### M01 事件类型枚举合法

- `事件类型` 只允许以下枚举值：
  - 点击
  - 曝光
  - 浏览
  - 时长
  - 其他
  - 性能（如当前治理规范保留该值）
- 出现枚举外值，判定为校验失败。

### M02 页面位置合法

- `页面位置` 必须命中 `configs/enums/page_locations.json` 的合法路径。
- 多页面位置时，必须使用英文逗号 `,` 分隔，每个值都要单独命中枚举。
- 若页面位置无法匹配，必须使用：
  - 页面位置：`无页面位置`
  - 页面位置中文标识：`server`

### M03 功能名称语义独立

- `功能名称` 必须表达业务功能/业务对象，不得承载事件类型语义。
- 命名要求可读、可复用，避免“无意义缩写 + 技术词”组合。
- `功能名称`中不得出现“点击、曝光、浏览、时长、性能、其他”这些事件类型枚举词
- 功能名称不能包含-，空格，、等等，不能以数字开头，可以包含汉字_，二十六个英文字母，空格，数字，但是数字不能作为开头

### M05 中文名拼接规范

- `埋点中文名` 必须满足：`cn_name-功能名称-事件类型`三段式规则。
- 当页面位置为多值时，按 `docs/workflow.md` 的多页面位置规则生成 `cn_name`。

### M06 场景命中后需一致

- 命中 `docs/domain_scenarios.md` 场景规则时，必须使用该场景的归一结果。
- 示例：英文名前缀 `list--` 命中列表刷新场景后：
  - 事件类型必须为 `浏览`
  - 功能名称必须与“推荐列表刷新”语义一致
  - 页面位置需尽量匹配“推荐相关”枚举路径

### M07 描述可解释

- `埋点描述` 必须能解释“在哪个场景、做了什么、为何上报”。
- 描述不得仅有“按钮点击”“页面曝光”等无上下文短语。

### M08 道具命中一致性

- 若埋点任一字段（`埋点中文名`/`埋点英文名`/`埋点描述`/`功能名称`）命中：
  - `configs/enums/B_items.json` 的 `tool_names`，或
  - `configs/enums/C_items.json` 的 `tool_names`
- 则该埋点必须按道具业务处理：
  - 页面位置优先使用道具相关枚举路径
  - 功能名称保留道具语义，不得泛化
- 若未满足，判定为校验失败。

## 3. 严格不能出现（Forbidden）

### F01 功能名称包含事件词

- `功能名称` 严禁出现以下词（含中英文变体）：
  - 点击 / click / tap
  - 曝光 / expose / impression
  - 浏览 / view
  - 时长 / duration
  - 其他 / other
  - 性能 / performance

### F02 虚构业务事实

- 严禁补充输入与需求文档中均不存在的业务事实。
- 严禁为了“凑完整”而臆造页面、功能、流程节点。

### F03 非枚举页面位置

- 严禁输出枚举外页面位置（服务端兜底场景除外）。
- 严禁使用不完整路径或自造路径。

### F04 中文名格式错误

- 严禁出现非 `cn_name-功能名称-事件类型` 结构。
- 严禁中文名中的事件类型与 `事件类型` 字段不一致。

### F05 场景命中后仍冲突

- 已命中高优先级场景规则却输出相反字段值，判定为严重错误。
- 示例：`list--` 前缀却输出 `事件类型=点击`。

### F06 多值页面位置分隔错误

- 严禁使用中文逗号 `，`、顿号 `、` 或空格替代英文逗号 `,`。

### F07 命中道具却未走道具页面

- 命中 B/C 道具词表后，若输出页面位置为非道具相关路径且无充分证据，判定为严重错误。
- 命中道具词表却直接使用 `无页面位置`（且并非明确服务端埋点）时，判定为严重错误。

## 4. 校验结论分级

- `PASS`：无错误，允许进入下游流程。
- `WARN`：仅存在建议项，不阻断（需记录）。
- `FAIL`：命中任一 Must 失败或 Forbidden 规则，必须修复后重试。

## 5. 失败处理原则

- 命中 `FAIL` 时，不得直接写回最终结果文件。
- 必须输出至少以下信息：
  - 规则 ID
  - 失败字段
  - 原始值
  - 建议修正值
  - 失败原因说明
- 修复后需重新执行全量规则，不允许“只跑单条规则”跳过回归校验。
